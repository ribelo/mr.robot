# Review: Mr. Robot v1.21 spec and tickets

Subject: `docs/issues/mr-robot-v1.21.md` and `docs/issues/mr-robot-v1.21/`.
Method: read the spec, all nine tickets, `GLOSSARY.md`, the v1.16, v1.18 and v1.20 specs, the Host app, the Host protocol, the Worker's places, memory, skills and prompt code, the PWA's Work details and Trajectory code, and the READMEs of the DSH 0.2.1-rc.2 packages the spec names. The DSH checkout is `/nix/store/jnd3lgmvk0cpw3qsqkgj0is2h63a7f4w-dsh-0.2.1-rc.2/lib/dsh`, called `$DSH` below.

Read-only review. No recommendations. Severities: **blocks the spec**, **should fix before implementation**, **note**.

Counts: blocks the spec 6, should fix before implementation 59, note 11. Total 76.

The three most serious: finding 1 (the Host must run DSH Agents to mount the named packages, which the spec's Out of Scope forbids), finding 13 and 14 (DSH cannot discover, start, stop or idle-stop language servers), finding 10 (worktrees give no isolation on a shared root, so stories 7 and 8 cannot both hold).

## 1. Claims about DSH packages, and DSH limits the spec ignores

1. **What.** The Host cannot mount `working-directory`, `tool-working-directory`, `tool-worktree`, `tool-lsp` or `agent-instructions` "unchanged" without DSH Agents and Sessions. Each requires one: the directory service is per Session and takes an Agent; the tool requires an Agent; the worktree tool "rejects calls without an Agent"; the lsp tool requires an Agent Session; the instructions plugin is wired to `agent/pre-step` with per-Session state.
   **Evidence.** `$DSH/packages/session/working-directory/src/index.ts:62-63` (`inject = ['fs', 'sessionProjections', 'systemPrompt']`, `ensure(agent)`), `$DSH/packages/session/tool-working-directory/README.md:80`, `$DSH/packages/experimental/worktree/README.md:28`, `$DSH/packages/experimental/tool-worktree/README.md:85`, `$DSH/packages/lsp/tool-lsp/README.md:52`, `$DSH/packages/context/agent-instructions/src/index.ts:36`, `$DSH/packages/context/agent-instructions/README.md:88`. Spec `docs/issues/mr-robot-v1.21.md:97` ("A Workspace session on the Host is keyed by Robot id"), `:60` ("mount ... unchanged"), and `:117` ("A second agent runtime on the Host" is out of scope).
   **Severity.** blocks the spec.

2. **What.** The instruction chain needs a process home. DSH resolves `$DSH_HOME` or `~/.dsh` and the shared root `~/.agents` from process policy, and ignores row keys that would point them elsewhere. A Host app started by systemd uses the service user's home, one chain for every Robot on that Host.
   **Evidence.** `$DSH/packages/context/agent-instructions/README.md:40` ("The harness home ... is process policy rather than row configuration ... Stray `dshHome` and `agentsHome` row keys are ignored"). Spec `:57`, `:59`, `:97`.
   **Severity.** should fix before implementation.

3. **What.** DSH's instruction refresh is touch-driven, not watched. A changed or removed `AGENTS.md` becomes visible only after a successful first-party `read`, `write` or `edit` from DSH's own tool runtime, or on resume. The Host app runs no DSH tools: Mr. Robot's file calls arrive as `Read` and `Write` RPCs. The spec's "exactly as DSH does" (cw-3zaq) therefore needs new logic on both sides, not the package.
   **Evidence.** `$DSH/packages/context/agent-instructions/README.md:34`, `:103`, `:219-220` ("there is no watcher"). Spec `:58`, `:60`, `:97`.
   **Severity.** should fix before implementation.

4. **What.** Instructions and skills are not bounded by the Workspace root. DSH's project root is the nearest ancestor with a `.git` marker, not the Workspace root. A Workspace at a repository subdirectory loads `AGENTS.md` and `.agents/skills` from above the root, and a Workspace outside any repository climbs to whatever repository contains it.
   **Evidence.** `$DSH/packages/context/agent-instructions/src/files.ts:232-247` (the walk up), `$DSH/packages/context/agent-instructions/README.md:42`, `$DSH/packages/skill/skill-filesystem/README.md:148` ("Project scope is the nearest `.git` ancestor"). Spec `:57`, `:59` name "the repository" without defining it against the Workspace.
   **Severity.** should fix before implementation.

5. **What.** Symlinked instruction files are followed across the trust boundary. A cloned repository can surface off-tree content, for example a private key or a token file, as workspace guidance in the Robot's baseline and therefore in the model request. The spec has no rule for untrusted repositories.
   **Evidence.** `$DSH/packages/context/agent-instructions/README.md:225` ("a cloned repository can surface off-tree file content as lower-authority workspace guidance ... Confine `ctx.fs` ... when loading untrusted repositories"). Spec `:30`, `:57`.
   **Severity.** should fix before implementation.

6. **What.** `agent-instructions` has no default budget: `maxBytes` is required, and the base profile passes 65,536 bytes. The spec says "maxBytes from the Robot's context budget", but the Robot's `contextBudget` is a token count for compaction and no token-to-byte rule exists.
   **Evidence.** `$DSH/packages/context/agent-instructions/README.md:30`, `:64` (`maxBytes` required), `packages/protocol/src/index.ts:517` (`contextBudget: Schema.Number`). Spec `:97`.
   **Severity.** should fix before implementation.

7. **What.** The memory baseline cannot take the instruction chain as designed. It is one message with a fixed 32,768-byte budget that drops the broadest entries whole. If the chain ranks as the most specific entry it is truncated last, and `AGENTS.md`, `MEMORY.md` and `SOUL.md` are dropped first. If it ranks as the broadest, the chain is dropped first and the baseline carries no instructions. The spec says the block goes "beside its memory" and also "gains a Workspace block", which are two different placements.
   **Evidence.** `apps/worker/src/robot/robot.ts:4283`, `apps/worker/src/plugins/memory.ts:95`, `apps/worker/src/agent/memory.ts:62-65` ("Your memory and persona files as of now"), `:79-92` (drop order), `$DSH/packages/context/agent-instructions/README.md:30`. Spec `:30`, `:97`.
   **Severity.** should fix before implementation.

8. **What.** `working-directory` is per Session, not per process or per Robot. The spec keys the Host's Workspace session by Robot id, which contradicts DSH's per-Session directory, the v1.19 chapter model (one DSH session per chapter) and Subagents (a second DSH agent each). A Subagent's `cd` or `create_worktree` would move its parent's directory.
   **Evidence.** `$DSH/packages/session/working-directory/README.md:12`, `:28`, `:42`; `src/index.ts:62-63`. `GLOSSARY.md:11` (Chapter is one DSH session), `:8` (Subagent). Spec `:97`.
   **Severity.** should fix before implementation.

9. **What.** Directory recovery would move a Robot to the Host app's launch directory. When the recorded directory disappears, DSH restores the original project, else the configured default, else `process.cwd()`. In a service that is the unit's working directory, not the Workspace. The spec does not say what happens when the owner moves or deletes the root.
   **Evidence.** `$DSH/packages/session/working-directory/src/index.ts:77` (`config.defaultDirectory ?? process.cwd()`), `README.md:80` ("prompt assembly rejects every model turn" when both are unavailable). Spec `:96`.
   **Severity.** should fix before implementation.

10. **What.** Worktrees do not isolate Robots that share a root. DSH creates the checkout under `<checkout root>/.agents/worktrees/<name>` and leaves the existing sandbox in force: "Creation does not widen write access". Under a v1.16 `workspace-write` grant the Workspace root must be a write root, which lets every Robot sharing that root write the whole repository, including the other Robots' worktrees. Story 7 ("without touching each other's files") and story 8 ("ten Robots in one repository") cannot both hold. Nothing confines writes to the new checkout.
    **Evidence.** `$DSH/packages/experimental/worktree/README.md:12`, `:37`, `:47`; `GLOSSARY.md:69` (write roots); `$DSH/packages/experimental/tool-worktree/README.md:37`. Spec `:51-52`.
    **Severity.** blocks the spec.

11. **What.** Worktree limits the spec ignores. Only committed content is copied: staged, unstaged, untracked and ignored files are not. There is no fetch, no submodule init, no dependency install, and missing local objects fail creation. Filters are disabled, so Git LFS pointers and encrypted blobs stay unhydrated. Branches and checkouts are retained with no removal path. Older Git that ignores `GIT_NO_LAZY_FETCH` may fetch from a promisor remote.
    **Evidence.** `$DSH/packages/experimental/worktree/README.md:35`, `:85-88`. Spec `:51` (cw-tmkf).
    **Severity.** should fix before implementation.

12. **What.** `create_worktree` returns `path`, `branch`, `baseCommit` and `repositoryRoot`, and requires an Agent. Ticket 03's acceptance says "path, branch and base", and a stub cannot test the directory move, which is DSH's `workingDirectory.set`. The bundle is off in every shipped profile.
    **Evidence.** `$DSH/packages/experimental/tool-worktree/README.md:28`, `:37`, `:85`. `docs/issues/mr-robot-v1.21/03-worktrees.md:9`.
    **Severity.** should fix before implementation.

13. **What.** The lsp package does not discover language servers and has no per-project configuration format. `lsp-stdio` requires an explicit `servers` record with `command` and `extensionToLanguage`; one bad entry prevents every provider from registering; the group ships no servers. This checkout has no LSP preset or configuration anywhere, so "as DSH Desktop does (its configuration format is reused)" has no referent.
    **Evidence.** `$DSH/packages/lsp/README.md:12` ("Deployments must supply and configure their language servers; this group ships none"), `$DSH/packages/lsp/lsp-stdio/README.md:12`, `:32`, `:51-52`. A grep of `$DSH/packages/bundle/base/cordis.patch.yml` finds no lsp row. Spec `:99`.
    **Severity.** blocks the spec.

14. **What.** The lsp package cannot stop servers with the Turn or after an idle time. It pools one process per (server, canonical workspace) and ends it only on service disposal. There is no Turn-end signal in the Host protocol, and a hard-killed app orphans the servers. The spec's "started on first use, stopped with the Robot's Turn or after ten idle minutes" needs new code in the provider.
    **Evidence.** `$DSH/packages/lsp/lsp-stdio/README.md:12`, `:67`, `:71` ("graceful shutdown happens only through service disposal"), `:149`. Spec `:65`, `:99`.
    **Severity.** blocks the spec.

15. **What.** Language servers run unconfined. The provider trusts its configured server and adds no sandbox, so the server has the filesystem and process authority of the execution world. For a coding Robot the server usually comes from the repository's own `node_modules`, so a cloned repository can run code as the owner on the first hover.
    **Evidence.** `$DSH/packages/lsp/lsp-stdio/README.md:75`, `:146`. Spec `:64`, `:99`.
    **Severity.** should fix before implementation.

16. **What.** The LSP workspace root is caller-supplied and required, and the spec never says whether it is the Workspace root or the current directory. The provider rejects query sources outside the canonical workspace and pools per root, and the model tool uses the session current directory. A `cd` creates a second server and changes what can be queried.
    **Evidence.** `$DSH/packages/lsp/lsp/src/types.ts:45` ("The workspace root ... required, never defaulted"), `$DSH/packages/lsp/lsp-stdio/README.md:67`, `:71`, `$DSH/packages/lsp/tool-lsp/README.md:28`. Spec `:99`.
    **Severity.** should fix before implementation.

17. **What.** DSH's `lsp` is a model-facing tool with no `on` argument and a generic search-card presentation. The Host cannot register a tool inside the Robot's Durable Object, so Mr. Robot's `lsp` would be a proxy with its own schema. "The only new code is the carrier" does not hold for it.

The Host adds only a PATH read from a login shell, and a systemd service runs with the unit's environment, not the owner's profile. Mr. Robot's `run` tool has no `env` parameter.
    **Evidence.** `$DSH/packages/shell/bash-local/README.md:84`, `$DSH/packages/subprocess/subprocess/README.md:12`, `:80`, `$DSH/packages/subprocess/subprocess/src/index.ts:47`; `apps/host/src/shell.ts:110-119`, `:300`; `apps/worker/src/agent/tools/places.ts:216-230`. 19. **What.** The Host's sandbox policy is a stub that exists only because `bash-sandbox` looks one up: it reports `read-only` and a home directory root. The worktree runtime, `working-directory` and `agent-instructions` also need a real `ctx.fs`, and `fs-local` (or another provider) is absent from the spec's composition list.     **Evidence.** `apps/host/src/shell.ts:4-6`, `:97-108`; `$DSH/packages/experimental/worktree/README.md:28` ("Mount ... alongside `workingDirectory`, `fs`, `subprocess`, `sandbox`, and `sandboxPolicy`"); `$DSH/packages/context/agent-instructions/README.md:30` ("providerless trees load nothing"); `$DSH/packages/lsp/lsp-stdio/README.md:28`. Spec `:97`.
    **Severity.** should fix before implementation.

20. **What.** Linux process ownership needs a user systemd manager. DSH launches ordinary processes in transient user scopes and checks `$XDG_RUNTIME_DIR/systemd/private`; a system service has no user manager and falls back to a process group with a warning, which can miss descendants that escape. A one-line Nix module does not create that environment.
    **Evidence.** `$DSH/packages/subprocess/subprocess-local/README.md:86`, `:149`. Spec `:77`, `:101`.

21. **What.** Jobs die with the app. The registry is in memory and process-local. A systemd unit that restarts on failure kills every running build, and the spec's service Host section says nothing about restarts or job loss.

22. **What.** DSH's confinement covers file effects only; network stays unrestricted. This is what lets a coding Robot fetch and install, and it is also what lets it send anything it reads. The spec treats the mode as the trust boundary.
    **Evidence.** `$DSH/packages/shell/bash-sandbox/README.md:32`, `:170` ("Confinement covers file effects only"). Spec `:68`, `:96`.

## 3. Missing pieces for a coding Robot on a Host

46. **What.** There is no credential story for git. No ticket or spec line covers an SSH agent, a deploy key, an HTTPS token or a git identity. Login entries are browser-only. The `run` tool has no environment, and DSH removes credential-shaped variables. Story 30 tells the Robot to "commit as the repository asks", and ticket 08 expects a commit.
    **Evidence.** `GLOSSARY.md:52` (Login entry fills pages), `apps/worker/src/agent/tools/places.ts:216-230`, `$DSH/packages/subprocess/subprocess/src/index.ts:47`. Spec `:84`, `:87`; `docs/issues/mr-robot-v1.21/08-acceptance.md:3`.
    **Severity.** should fix before implementation.

47. **What.** Secrets in a repository have no rule. Reads are as wide as the OS user in every mode, and the instruction chain reads the repository automatically. `.env` files, tokens and key material reach the Robot's context and the model provider without a call. The prompt's only rule about credentials is about writing them.
    **Evidence.** `docs/issues/mr-robot-v1.16.md:27` ("Reads stay as wide as the OS user"), `GLOSSARY.md:68`, `apps/worker/src/agent/platform-prompt.ts:99`; `$DSH/packages/context/agent-instructions/README.md:225`. Spec `:30`, `:57`.
    **Severity.** should fix before implementation.

48. **What.** Two writers on one root clobber each other. `edit` reads the whole file, replaces text and writes the whole file back. `Write` carries no expected size, hash or version, and there is no lock or lease. Story 8 puts ten Robots on one root, and the owner may edit the same file at the same time.
    **Evidence.** `apps/worker/src/agent/tools/places.ts:160-168`, `apps/worker/src/places/files.ts:72-78`, `packages/host-protocol/src/index.ts:62-66`. Spec `:52`.
    **Severity.** should fix before implementation.

49. **What.** A write cut off by a lost link has no defined outcome. The Host handler returns a failure when the call fails, but the file may already be written; the Worker cannot tell. There is no idempotency key, and a retry can overwrite a change made in between.
    **Evidence.** `apps/host/src/handlers.ts:33`, `apps/host/src/connection.ts:45-71` (reconnect and retry), `apps/host/src/files.ts:72-78`. Spec has no line.
    **Severity.** should fix before implementation.

50. **What.** Size limits are unstated. The Host refuses a read above 10 MB, the read window shows at most 2,000 lines and 50 KiB, and a write sends the whole file as one JSON frame. Binary files come back as base64, which doubles them, and cannot be edited at all.
    **Evidence.** `apps/host/src/files.ts:14`, `:63`; `apps/worker/src/places/file-ops.ts:6-8`; `packages/host-protocol/src/index.ts:55-66`; `apps/worker/src/agent/tools/places.ts:162-166`. Spec `:69`.
    **Severity.** should fix before implementation.

51. **What.** Line endings break edits on Windows. The read window strips a trailing carriage return for display, while `edit` matches the raw text. A model that saw LF lines cannot reproduce a CRLF file's text, so every multiline edit in such a repository fails with "the text to replace was not found".
    **Evidence.** `apps/worker/src/places/file-ops.ts:16` (strip CR), `:42-49` (exact match); `docs/issues/mr-robot-v1.16.md:29` (Windows Host). Spec `:117` leaves only Windows LSP out of scope.
    **Severity.** should fix before implementation.

52. **What.** Choosing and validating a root is not designed. The Workspace is a free string. No RPC lists directories, checks that the path exists, or checks that the Robot holds a facet on the named Host. The existing validator, `isHostRoot`, is only for write roots.
    **Evidence.** `packages/host-protocol/src/index.ts:37-43`, `apps/worker/src/robot/host-access.ts:72-86`, `apps/worker/src/places/place.ts:167-178`. Spec `:96`, `:97`.
    **Severity.** should fix before implementation.

53. **What.** Subagents are absent from the spec. Three can run at once with the Robot's grants, including places, and they share the per-Robot current directory and worktree. A Subagent can move its parent's directory or write in its checkout.
    **Evidence.** `GLOSSARY.md:8`, `:16`; `apps/worker/src/places/places.ts:41-69`. Spec has no line.
    **Severity.** should fix before implementation.

54. **What.** A Workspace on the Box is nearly useless for code. The Box disk is scratch; only `box/` survives, and that folder is copied at every boot. The spec allows "the Box and /workspace" as a Workspace without a caveat.
    **Evidence.** `GLOSSARY.md:43`, `apps/worker/src/skills/platform.ts:276-278`, `apps/worker/src/docs/box.ts`. Spec `:26`, `:96`.
    **Severity.** note.

55. **What.** There is no pty and no persistent shell on a Host, so a TTY prompt (a passphrase, `npm login`, a `gpg` prompt) and a shell that keeps a watcher cannot work. v1.16 put a persistent terminal out of scope; v1.21's coding Robot is built on interactive workflows and does not restate it.
    **Evidence.** `apps/host/src/shell.ts:4-6`, `apps/host/package.json` (no terminal packages), `docs/issues/mr-robot-v1.16.md:144`. Spec `:36`, `:84`.
    **Severity.** note.

56. **What.** The Workspace panel's git commands run against repository-controlled configuration. The panel would run `git status` and `git log` itself, and `git status` can run a configured fsmonitor program. DSH's own worktree code disables configured filters for exactly this reason.
    **Evidence.** `$DSH/packages/experimental/worktree/README.md:35`, `:87` ("checkout skips configured filters to avoid executing repository-configured programs"). Spec `:100`.
    **Severity.** should fix before implementation.

57. **What.** No Host-side lifecycle for a Workspace session. Nothing closes the session when the Robot's Workspace changes, the Robot is deleted, the Host is unpaired or the app quits. Language servers live until service disposal, and jobs are stopped only on unpair.
    **Evidence.** `$DSH/packages/lsp/lsp-stdio/README.md:71`, `:149`; `apps/host/src/connection.ts:84-90` (unpair stops jobs); `apps/host/src/main.ts:69` (`hostShell?.dispose()` on Quit). Spec `:97`.
    **Severity.** should fix before implementation.
