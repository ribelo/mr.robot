## Answers to the questions put to this review

- **Persona fold run twice.** In the happy path no: `persona-folded` is checked and set around one call (`robot.ts:2839-2845`), and the MEMORY.md shape is idempotent because `shapeMemory` returns undefined once the three headings exist (`persona-fold.ts:59-66`). A fold that fails after writing SOUL.md/AGENTS.md and before removing IDENTITY.md/TOOLS.md repeats the append on the next Turn (finding 5). A Robot that wrote its own `## Tool notes` gets a second one (finding 5).
- **MEMORY.md headings on a file that already has some.** `shapeMemory` appends only the missing headings, so no text is lost; it does not reorder sections and does not detect headings inside a code fence (a `## Facts` line in a fenced example counts). No data-loss path found.
- **The `home` → `space` object copy on a partially copied state.** The copy is one SQLite transaction inside `blockConcurrencyWhile`, guarded by "the new object's `member` table has no rows", and `member` rows are never deleted (`remove` only sets status), so a retry after a committed copy skips it and a retry after a rolled-back copy repeats it: no duplication and no partial copy was found. The risks are size/blocking (finding 29) and the old object's background work after the move (finding 30).
- **Store migration 28.** It is idempotent and covers the config's `sharing`, `spendLimit.kind` and an open skill proposal's `visibility` (`store.ts:321-327`); the Space registry, Host and skill rows are renamed every start (`space.ts:1345-1351`) and the Member's Host table at start (`member/hosts.ts:109-110`). The gaps are on the wire, not in storage (finding 23), and in the Hosts UI (finding 2).
- **Owner scrub leak.** Yes, by construction: the scrub step sees only the staged persona and skills, and the platform then adds `tasks.yaml` (Task titles and instructions verbatim), `grants.yaml` and a fallback README from `identity.description` (`robot.ts:3899-3904`); nothing checks the scrub's result (finding 15).
- **YAML safety.** 1.2 core schema, strict, unique keys (`definition.ts:63`), excess properties refused by the Effect schemas, `no`/`off` stay strings, and the `yaml` 2.9.1 default `maxAliasCount` 100 bounds alias expansion (`node_modules/.pnpm/yaml@2.9.1/node_modules/yaml/dist/nodes/Node.js:28`, `Alias.js:61-66`). There is no document size cap (finding 31).
- **Grok importer against a hostile page.** The pasted URL is restricted to `https://x.ai/bot/marketplace/bots/<slug>` (`grok-import.ts:44-56`), but the fetch has no size or time bound, runs inside the single Space Durable Object, follows redirects, and the marker/brace scan is quadratic on a page whose template repeats the `{"id":"<slug>"` marker (finding 17).
- **tar.gz download.** Not bounded: `DefinitionLibrary.files` loads every file into a Map and `definitionArchive` builds the tar and gzip in memory (`library.ts:58-70`, `tarball.ts:38-51`). Names longer than 100 bytes in one segment are silently truncated (`tarball.ts:6-35`); the sync reader does not normalize `..`/absolute paths (finding 16).
- **History trimming.** 50 is enforced after each kept version; the 90-day rule is only applied when a new version is kept, so an untouched file keeps versions older than 90 days (finding 13). A restore writes the chosen text over the current file with no conflict check; a write that arrived after the drawer opened is displaced (it survives as a version) (finding 12).
- **The sweep and Turns.** The sweep never starts during a Turn, but a Turn can start during the sweep; then the fence refuses the Turn's tools, the sweep's step limit cancels the combined agent run, the Turn's writes are labelled "the memory sweep" until the step ends, and its usage is booked under memory (finding 9). The sweep's tool allow-list restricts the Place, not the paths: it can write any Workspace file (finding 8).
- **One-release aliases.** The list in ticket 09 matches the storage readers, but the wire is incomplete: `wholeHome` on `PATCH /api/me` is ignored, and `withSpaceValues` rewrites any string `home` under any key named `scope` (finding 23). The Hosts select still uses `value="home"` (finding 2). The Alchemy class-rename migration has no test that asserts it (finding 24).
